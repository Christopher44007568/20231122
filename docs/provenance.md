# 溯源与边界处理设计

## 六阶段处理流水线

每个结论都记录经过的阶段顺序（`StepRecord.order`），并在证据中保留输入行号
与原始文本：

1. `INGEST` 逐行读取，不重写、不重编号。
2. `PARSE` 切分 `key: value`，问题以 `E1xxx` 记录并保留行号。
3. `NORMALIZE` 去空白、状态值转小写，仅改变派生值，原始行不变。
4. `CLASSIFY` 识别重放状态、已知/未知扩展。
5. `CORRELATE` 比对校验和、帧数、首个分歧帧、扩展知识库。
6. `CONCLUDE` 汇总自动结论、人工确认、失败与边界证据。

## 结论如何回到原始输入

- `Finding.evidence` / `ManualCheck.evidence` / `FailureReport.evidence`
  均为 `EvidenceRef{sourceLine, quote}`，可直接定位到 `Report.lines`。
- `Finding.steps` 引用 `StepRecord.order`，可回放该结论经过的处理步骤，
  每个步骤还分别记录输入与输出证据。
- GUI 第 5 节与文本报告都附完整原始转储，人工核对无需另找文件。

## 无法判断的边界（不猜测原则）

样本中的 `VK_VENDORX_phantom_inference` 不在知识库内，流水线只能给出
`INDETERMINATE`，并：

- 保留原始扩展行（样本第 12 行）作为关键证据；
- 在 `Report.manualBoundaryLine` 记录边界行；
- 生成人工确认项和三条可执行操作（查注册表、禁用 A/B 复现、供应商工单）。

重放分歧帧（样本第 16 行）同样无法自动判定严重程度，边界行优先保留先
出现的不可自动判定证据。

## 失败时的可执行后续操作

| 失败码 | 触发条件 | 后续操作是否阻塞 |
| --- | --- | --- |
| `F1001` | 存在无法解析的行 | 阻塞，修复行或重新导出后重跑 |
| `F2002` | 必需身份字段缺失 | 阻塞，重新采集完整字段 |
| `F2003` | 无恢复后重放记录 | 阻塞，运行恢复工具并附上命令流 |
| `F2004` | 校验和不一致 | 阻塞，重新恢复并检查拷贝链路 |

CLI 遇到任一失败返回退出码 `2`，便于接入自动化流水线。

## 自动结论与人工确认分离

报告与 GUI 均分成两个独立区块：`Automatic conclusions` 只放可由规则闭环的
判定；`Manual confirmation required` 只放需要人判断的项目，二者不混排，
避免把人工意见误读成机器结论。
